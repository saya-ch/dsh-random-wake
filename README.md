## 这是什么场景

你有一个常聊的会话 —— 可能是挂在 QQ 上的角色，也可能是一个你自己每天都要开一次的工作会话。

**正常情况下，你不说话，它就永远停在上一句。** 它不会想起你，也不会主动开口。

装上这个插件之后，它会**自己按不固定的节奏醒一下**：醒来看看要不要说点什么，说完或者决定不说，再睡回去。醒来的时候你不一定在，所以你回来时可能发现它已经主动找过你了。

它要解决的就是一件事：

> **让"你不理它，它也不出声"变成"隔一阵它自己会来一下"。**

### 什么时候用得上

| 场景 | 没有它 | 有它 |
|---|---|---|
| **AI 陪伴 / 角色扮演** | 你不发消息，角色永远不会主动找你 | 角色按自己的作息偶尔主动开口，像真人一样 |
| **养着的 QQ 机器人** | 只有被 @ 才动 | 会自己挑时候来一句，不再是纯应答机 |
| **每日工作会话** | 每天手动开一次，贴一遍背景 | 让它在你习惯的时间段自己醒来看一眼 |
| **测试长会话行为** | 手动盯着发消息 | 让它在后台持续被唤醒，观察上下文怎么长 |
| **验证某个提示词** | 手动反复发 | 设成高频，看模型在真实唤醒下的真实反应 |

### 什么时候**不该**用它

- 想要**准点提醒**（每天 9:00 叫你）→ 用 DSH 内置的「自动化任务」，它更合适
- 想要**一次性延时任务** → 同上
- 想要**上下文自动压缩** → 它是另一个问题，本插件不做

## 核心区别：为什么是"随机"

这是这个插件唯一真正特别的地方。

内置定时任务知道"几点几分该做什么"。但**真人不是这样的** —— 没人会在每天 9:00:00 整准点给你发消息。

所以这里的节奏由两重随机决定，**都发生在宿主进程里，模型完全无法干预**：

```
1. 什么时候检查        →  间隔 × (1 ± 浮动)      每次都不一样
2. 这次要不要真的开口  →  掷一次骰子，不中就不叫醒
```

具体来说，配置「间隔 30 分钟、浮动 ±40%、概率 25%」，实际行为是：

- 每 **18 ~ 42 分钟**（随机）检查一次
- 每次检查只有 **1/4** 的概率真的唤醒
- 所以**平均一个多小时才会醒一次**，而且时间点毫无规律
- 剩下 3/4 的检查**一分钱 token 都不花** —— 判否时根本不调用模型

这一点很关键：`Math.random()` 只存在于宿主代码里。模型收到的消息是「有人叫醒你了」，不是一个「掷骰子决定要不要说话」的任务 —— **它没法通过说错话来影响自己被唤醒的频率**。

## 快速开始

```bash
# 从 npm 安装（推荐）
dsh plugin --profile <profile> add dsh-random-wake

# 或从本地源码安装（开发时用 link:，不是 file: —— 原因见「开发」一节）
dsh plugin --profile <profile> add link:/absolute/path/to/dsh-random-wake

# 然后确认 profile 的 dsh.profile.bundles 含 "dsh-random-wake"，重启 DSH
```

打开右侧栏 →「**随机唤醒**」→ 粘贴会话 ID 或点「用当前会话」→「添加」→ 点「参数」选一个预设。

第一次验证建议：

1. 选 **日常搭话**
2. 把「闲置守卫」临时改成 `0`
3. 点「立即触发」

看到会话里多出一条提示条 + 模型回复，说明链路通了。

## 它会怎么醒过来

每个会话到点后按顺序过闸门，**全部通过**才真正唤醒：

```
开关 → 有无目标 → 静默时段 → 每日上限 → 冷却 → 概率抽签 → 目标忙否 → 投递
任何一个 ✗  →  不调用模型，只把下一次重新排上
```

通过之后：

1. 目标会话没在跑就 `agents.resume()` 冷启动它
2. 有未结束的回合则让开（`target-busy`），不打断正在生成的回答
3. 投递一条 **`form: "notice"` 的 user 消息** —— GUI 里显示为提示条，**不是伪造的用户发言**
4. 等这一轮跑完，释放句柄

模型收到的是一条**自我唤醒**的框架消息：

```
[self-wake 2026-11-14 19:57]
This is not a message from the user. You woke up on your own — something crossed your mind and you felt like saying it.
没什么事发生，是你自己忽然想起了他。想说什么就自然开口，不想说就安静结束本回合，不要输出任何文字。
```

要点：

- **不伪造用户发言** —— 第二行明确写着"这不是用户发来的消息"，所以模型不会把它误读成你主动开口
- **但语义是"自己想动了"** —— 不写"宿主定时唤醒"这类机械措辞，而是把这一刻框定成角色自己忽然想起对方
- 时间戳只保留 `self-wake` 标记和本地时间，供模型判断"现在几点"，不暴露调度细节

然后它**自己决定说还是不说** —— 不想说就直接结束回合，不输出任何文字。这一层是自由的：插件只管"什么时候叫醒"，不管"叫醒之后说什么"。

## 闸门详解

每个闸门都是纯函数判断，**判否的路径不产生任何模型调用**。

### `enabled` — 总开关

关掉时这一项完全休眠，计时器不 arm。

### `sessionId` — 目标会话

空字符串直接跳过。

### `quietStart` / `quietEnd` — 静默时段

`HH:MM`，左闭右开，**支持跨午夜**：

| 配置 | 含义 |
|---|---|
| `01:00 → 08:00` | 凌晨 1 点到早 8 点静默 |
| `23:30 → 09:00` | 晚 11 点半到早 9 点静默（跨过零点） |

判定发生在**概率抽签之前**，不会白白消耗概率。

### `maxPerDay` — 每日上限

按本地日期计数，零点归零。只在**真实投递成功**时 +1。

### `cooldownMinutes` — 冷却

距上次真实投递不足该分钟数则跳过。建议 **≥ 间隔**，保证"说完一句不会立刻又来一句"。

### `probabilityPct` — 概率抽签

`0~100`。到这一步掷一次：

```js
if (Math.floor(Math.random() * 100) >= probabilityPct) return skip('probability')
```

`0` 可当临时熔断，`100` 必中。

### `targetBusy` — 目标忙否

只在投递前检查：目标有未结束回合就放弃本次，不打断生成。

### `idleGuardMinutes` — 闲置守卫

目标会话最近活动距今不足该分钟数则跳过。**冷会话天然视为已闲置**。

**手动触发会绕过这一闸门** —— 它服务于"等对方安静了再开口"的自动节律，不该拦住用户主动点击。

## 时间是怎么排的

每个会话各自独立重排，互不干扰：

```
下次触发 = 现在 + intervalMinutes × (1 + uniform(-jitterPct, +jitterPct))
```

举例（间隔 30 分钟）：

| `jitterPct` | 实际间隔范围 | 观感 |
|---|---|---|
| 0 | 恒定 30 分钟 | 闹钟，不像人 |
| 20 | 24 ~ 36 分钟 | 有波动，但仍规律 |
| 50 | 15 ~ 45 分钟 | 明显不规则 |
| 100 | 0 ~ 60 分钟 | 时快时慢，最不规律 |

浮动是**每次触发后重算并固化**的，不是每 5 秒重算 —— 倒计时稳定，不会跳。

## 节奏预设

面板「参数」里的一排胶囊，点一下把整套时间参数换掉并**立即保存**。

| 预设 | 间隔 | 浮动 | 概率 | 每日 | 冷却 | 闲置 | 静默时段 | 观感 |
|---|---|---|---|---|---|---|---|---|
| 日常搭话 | 25min | ±40% | 25% | 5 | 35min | 8min | 00:30–08:30 | 平均一两小时一次，多数检查沉默 |
| 慢热 | 60min | ±50% | 15% | 2 | 60min | 20min | 23:30–09:00 | 一天最多 2 次，被拒也不追 |
| 话多 | 15min | ±45% | 40% | 12 | 10min | 3min | 02:00–07:30 | 十来分钟看一眼，四成会开口 |
| 夜猫子 | 40min | ±35% | 30% | 4 | 30min | 5min | 05:00–12:00 | 上午静默，夜里活跃 |
| 早晚问候 | 120min | ±25% | 60% | 2 | 120min | 15min | 22:30–07:00 | 两小时一检查，一天两次机会 |
| 一杯茶 | 90min | ±45% | 35% | 4 | 90min | 12min | 00:00–09:00 | 两三个小时才想起一次 |
| 上班时段 | 45min | ±30% | 30% | 6 | 40min | 10min | 18:30–09:30 | 只在上半段活跃 |
| 深夜陪聊 | 25min | ±50% | 45% | 8 | 15min | 2min | 03:00–13:00 | 零点前后最活跃，午后收声 |
| 周末闲散 | 50min | ±60% | 35% | 6 | 45min | 15min | 01:00–10:00 | 间隔拉得很散 |
| 偶尔想起 | 180min | ±40% | 25% | 1 | 180min | 30min | 22:00–10:00 | 一天最多一次，几乎不打扰 |
| 一阵一阵 | 20min | ±100% | 50% | 8 | 5min | 2min | 02:30–08:00 | 偶尔连说几句，然后长时间安静 |

### 为什么这样配才像人

改参数时建议保持这六条：

1. **浮动给足**（35%~50%）—— 固定间隔立刻暴露是机器
2. **概率压低**（15%~40%）—— 真人不是每次想起都说话
3. **冷却 ≥ 间隔** —— 避免连发两条
4. **闲置守卫 > 0** —— 等对方安静下来再开口，而不是插话
5. **静默时段覆盖睡眠** —— 夜里完全不出现
6. **每日上限兜底** —— 防止抖动叠加导致某天暴走

## 备注名与会话标题

**备注名是用户自己的标签**，加入列表那一刻从会话标题取一次快照，之后冻结。

会话改名不影响备注 —— 它的定位是"我给它起的名字"，不是标题的实时镜像。

- 加入时若备注为空，宿主读一次该会话的 `session/title` 事件：
  - **活跃会话** → `ctx.sessionTitle.get(session)`，折叠 live 事件
  - **冷会话** → `sessionPersistence.open(id, 'read')`，读日志倒序找最后一条 `session/title`
- 冷会话标题有 **60 秒缓存**，避免 4 秒轮询反复读日志
- 卡片主标题 = 备注名 → 实时标题 → 短 ID，逐级回退
- 副标题固定显示 `实时标题 · 短ID`，便于对照

## 数据结构

`$DSH_HOME/random-wake/config.json`（默认 `~/.dsh/random-wake/config.json`）：

```json
{
  "targets": [
    {
      "id": "t-m3k2a-9x2p1",
      "sessionId": "session-1a2b3c4d-...",
      "label": "会话 A",
      "enabled": true,
      "intervalMinutes": 30,
      "jitterPct": 40,
      "probabilityPct": 25,
      "quietStart": "00:30",
      "quietEnd": "08:30",
      "maxPerDay": 5,
      "cooldownMinutes": 35,
      "idleGuardMinutes": 8,
      "prompt": "过了一段时间了，给他发句话吧~"
    }
  ]
}
```

| 字段 | 类型 | 范围 | 说明 |
|---|---|---|---|
| `id` | string | — | 内部标识，自动生成 |
| `sessionId` | string | — | 目标会话 ID |
| `label` | string | — | 备注名（用户标签，冻结） |
| `enabled` | boolean | — | 总开关 |
| `intervalMinutes` | number | 1~1440 | 基准间隔 |
| `jitterPct` | number | 0~100 | 随机浮动百分比 |
| `probabilityPct` | number | 0~100 | 触发概率 |
| `quietStart` / `quietEnd` | string | `HH:MM` | 静默时段，支持跨午夜 |
| `maxPerDay` | number | 0~999 | 每日上限 |
| `cooldownMinutes` | number | 0~1440 | 冷却 |
| `idleGuardMinutes` | number | 0~1440 | 闲置守卫 |
| `prompt` | string | — | 唤醒消息正文 |

**旧格式自动迁移**：早期单目标格式（顶层直接是 `enabled` / `sessionId` / ...）加载时自动折叠成一条 `targets` 记录。

**运行时状态不落盘**：`下次时间` / `今日次数` / `最近记录` 只在内存，重启后归零或重排。重启后重新排期，比恢复一个过期倒计时更符合直觉。

## HTTP 接口

两条同源路由，走 DSH 官方 `connection.fetch` 闸门：

### `GET /api/random-wake/state`

返回所有受管会话的完整快照（配置 + 运行时状态 + 标题）。

### `POST /api/random-wake/targets`

统一变更入口，`op` 区分操作：

```jsonc
// 添加
{ "op": "add", "target": { "sessionId": "...", "enabled": true } }
// 更新（部分字段）
{ "op": "update", "target": { "id": "t-...", "probabilityPct": 50 } }
// 移出
{ "op": "remove", "id": "t-..." }
// 手动触发
{ "op": "fire", "id": "t-..." }
```

响应统一是变更后的完整快照，出错带 `error` 字段（`no-target-session` / `already-managed` / `unknown-target` / `unknown-op` / `bad-json` / `forbidden`）。

## 权限与安全

- **只有 owner 能调用**：路由经 `ctx.connection.admit()` 校验，非 owner 直接 403，无 connection 服务时一律拒绝
- **只写一个文件**：除 `random-wake/config.json` 外不落盘任何东西
- **不联网**：没有任何外部请求
- **不碰你的 git**：不做快照、不提交、不改索引
- **不伪造用户发言**：唤醒消息携带 `source.kind = "plugin:dsh-random-wake"` 与 `form: "notice"`
- **未列入列表的会话零影响**：不持有引用、不起计时器、不投递

## 与其他方案的区别

| | 内置 `dsh-schedule` | dsh-proactive | dsh-heartbeat | **dsh-random-wake** |
|---|---|---|---|---|
| 随机触发时刻 | ❌ | ✅ jitter | ✅ ±20% | ✅ jitter |
| 概率决定是否触发 | ❌ | ❌ 必唤醒，靠模型静默 | ⚠️ 规则闸门，非骰子 | ✅ **代码层掷骰** |
| 每会话独立节奏 | ❌ | ✅ | ❌ 全局一套 | ✅ |
| 上下文折叠 | ❌ | ✅ 墓碑 | — | ❌ |
| 附带功能 | 无 | 无 | 素材池/画像/B站 | **无，只做闸门** |
| 面板位置 | 自动化任务页 | 会话 Tab | 独立面板 | **右侧栏 Tab** |

选择建议：

- 只要"按点提醒" → 内置 `dsh-schedule`
- 想要"AI 陪伴感"，能接受一整套附加功能 → `dsh-heartbeat`
- 只要"外部掷骰子决定唤不唤醒，其他一概不要" → 本插件

## 开发

无需构建，源码即产物。

```bash
node --check index.js
node --check client.js

# 本地联调：用 link: 安装，改完源码重启 DSH 即可
dsh plugin --profile <profile> add link:/absolute/path/to/dsh-random-wake
```

> ⚠️ **必须用 `link:` 而非 `file:`**。`file:` 会让 pnpm 把目录**复制**一份到 profile 的 `node_modules`，之后你改源目录、DSH 读的还是旧副本 —— 这就是"改了没生效"的经典陷阱。`link:` 建的是目录联接，源与安装点是同一份文件。

### 源码结构

| 文件 | 职责 |
|---|---|
| `index.js` | 宿主侧：配置读写、每目标计时器、六道闸门、`agents.resume()` 唤醒、标题折叠、两条 HTTP 路由 |
| `client.js` | 浏览器侧：右侧栏 Tab、会话卡片、11 个预设、内联布局 |
| `cordis.patch.yml` | bundle patch 层，单行 insert |
| `package.json` | `dsh.bundle.patch` + `dsh.client.inject` |

### 改宿主代码后

`index.js` 改动**必须重启 DSH**。Node 的 ESM 模块缓存不会因为插件 `disable → enable` 而失效 —— 热重载只重新执行 `apply()`，读不到新文件。

`client.js` 改动只需 **Ctrl+R 刷新页面**。

## 已知限制

- **运行时状态不持久**：今日次数、下次时间、最近记录都在内存，重启归零
- **只唤醒已有会话**：不支持 fork / 新建会话
- **不折叠上下文**：每次真实唤醒的完整交换都留在会话上下文。高频（< 15 分钟）要自己留意窗口增长
- **静默时段只按时间判断**：不区分工作日/周末。"上班时段"预设下班后静默，但周六周日照常运行
- **未验证更高版本**：只在 DSH `0.2.2-rc.1` 上跑过
- **手动触发不校验概率**：有意设计，用于调试，不是漏洞
